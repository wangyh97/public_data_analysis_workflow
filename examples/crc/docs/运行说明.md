# 运行与复现

## 快速重现图表

在 PowerShell 中进入本目录，执行：

```powershell
.\run_analysis.ps1 -Mode analyses
```

默认使用已有 `derived/` 检查点，重新生成样本/患者汇总、统计、图表和敏感性分析。原始数据不会被改写。运行失败会停止，错误所在步骤的完整日志保存在 `audit/步骤名.run.log`。

## 从原始下载重新执行

```powershell
.\run_analysis.ps1 -Mode full
```

`full` 包括官方网页/大小核对、GEO 缺失文件续传、scCT 压缩包验证与 CRC 提取、CellResDB RDS 提取、完整 GEO 矩阵提取、临床映射、统计及绘图。网络访问只用于公开数据 GET/HEAD，不上传本地数据。已有 RDS/部分提取步骤会复用对应完成检查点。需要强制重新提取时，先备份结果，再仅删除要重建的对应 `derived/` 检查点；不要删除原始下载。

仅补下载/验证下载：

```powershell
.\run_analysis.ps1 -Mode downloads
```

## 路径和依赖

本仓库的入口通过 `examples/crc/run.py` 的命令行传入路径，运行时生成 `analysis_config.json`；本段保留历史环境的软件版本信息。实际路径以该次 `run_manifest.json` 为准：

| 项目 | 本次实际配置 |
|---|---|
| R | R 4.4.2；运行时 `--rscript` 指定路径 |
| Python | 运行时 `--python` 指定路径 |
| Node.js | 运行时 `--node` 指定路径 |
| 源目录 | 运行时 `--source-dir` 指定路径 |
| 输出目录 | 本 `CRC_single_cell` 文件夹，由脚本位置自动定位 |

本次使用系统已有 R 4.4.2、Matrix 1.7-1、ggplot2 3.5.1，以及已有 data.table、jsonlite；详细包版本和平台见 `audit/R_final_sessionInfo.txt`。Python 只用标准库与已有 NumPy，Node 只用内建 `fs/path/zlib/events`。首轮没有修改系统 R/Python，也没有安装新包；后续 CellChat 扩展在项目 runtime/R-library 中安装了缺失依赖，详见 CellChat运行与设计.md。R 启动时本机的 `C.UTF-8` locale 警告保留在日志中；各分析脚本使用 UTF-8 文件和明确字段名。

本机内存约 23.5 GiB。不要直接 `readRDS()` 同时载入五个多 GB 的 GSE236581 Seurat 对象，也不要把完整稀疏矩阵转为 dense。文件提取采用逐文件/流式读取；最终只保存 79 个目标及功能基因的紧凑矩阵，同时使用全部输入基因计算文库大小。基因列表由 `02_extract_cellres.R` 的注释清晰的 `genes` 向量定义，功能模块和统计参数由 JSON 定义。修改功能模块时需要确保新基因加入提取列表并重建对应检查点。

## 固定参数

- 随机种子：20260905。
- 目标：METTL3、STRAP、PTBP1；不得再使用误拼 STARP。
- log-normalization：全输入基因文库分母，CP10K，`log1p`。
- 患者 bootstrap：1,000 次；报告边际 95% 区间。
- 主要 MHC/APM family：每研究、Pre、明确恶性细胞中的 3 个目标 × 2 个分数，BH 校正。
- 其余相关按研究/平台在 exploratory family 中校正；response 的 3 个目标在对应研究/平台/阶段/细胞定义内校正。不同 family 不能混读 q 值。
- 最低细胞/患者数见 JSON；敏感性分析使用恶性细胞门槛 10、30、50、100。
- GEO 大矩阵按 CSC 顺序逐条校验坐标有序、唯一、范围与非负整数；若文件格式/顺序改变，读取器会明确失败。
- 下载：1 MiB 写入块，HEAD 90 秒、GET 120 秒超时，最多 8 次恢复尝试；`Range` 必须获得 206 响应才能追加；`.part` 达到预期长度后才改为正式文件。

## 复查重点

1. `audit/analysis_cell_coverage.csv`：输入、重复样本排除、未映射 CRC 排除与实际纳入。
2. `tables/patient_response_mapping.csv`：回填、冲突与最终方案，禁止凭患者编号跨研究合并。
3. `tables/analysis_eligibility.csv`：每个比較的真实患者数，哪些 response 比较因 NR 太少不执行。
4. `tables/correlations_all.csv`、`response_tests.csv`：全部结果，不只显著项。
5. `tables/primary_independent_studies.csv`：独立研究主分析数据，不把 GEO 与 CellResDB 同一患者重复计作验证。
6. `audit/*_library_vs_metadata.csv`：矩阵重算文库大小与保存的 QC 元数据是否相同；任何差异须结合基因过滤步骤解释。
7. 修改参数后，重新运行 `analyses` 并保留新运行的配置与日志，避免只替换图片。

## CellChat 扩展和原始 QC 边界

此前未执行的 CellChat 扩展现已完成。见 `CellChat补充报告.md`、`CellChat运行与设计.md`，配置为 `cellchat_config.json`，入口为 `run_cellchat.ps1`。快速重画使用 `./run_cellchat.ps1 -Mode compare`；完整扩展流程使用 `./run_cellchat.ps1 -Mode all -Workers 4`。原先 `run_analysis.ps1` 保持原主分析范围。
